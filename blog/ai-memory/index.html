How AI Remembers: Context and Compacting

llmsengineeringResearched October 2026

Every AI conversation runs on a working memory called the context window: one shared token budget for the prompt, the whole history, and the answer being written. It fills up as you talk, it costs real money per token, and when it overflows the oldest turns collapse into a summary. The sentence to remember: an AI's memory is a desk, not a hard drive, and whoever controls what stays on the desk controls what the AI knows.

1. The brief

AI looks like it remembers everything. It does not. A model has two kinds of memory. The first is baked into its weights during training: facts, patterns, vibes, frozen at the cutoff date. The second is the context window: the live working memory of this conversation, and the only place new information can go. That window is limited, it is shared by everything including the answer being written, and the infrastructure underneath charges rent by the token.

The last two years turned this from trivia into the central engineering problem of agents. Windows grew to a million tokens. Summarization got automated into an API primitive called compaction. And everyone building long-running agents learned the hard rule: anything that matters goes in a file, because everything else is one summary away from being gone.

What survives the summary, what gets fuzzy

Compaction does not treat all context equally. What survives depends on how it was loaded, not how important it was. Flip the switch.

  • System prompt and output style. Never part of the message history, untouched by every compaction.
  • Files on disk. The project-root CLAUDE.md and auto-memory files are re-injected from disk at session start, summary-proof.
  • Saved memories. ChatGPT stores them separately from chat history and considers them in every future response, even after the chat is deleted.
  • Recent turns. On-demand compaction keeps the last few turns word for word and only summarizes the older ones.
  • Invoked skills. Their bodies are re-injected, capped at 5,000 tokens each and 25,000 total, oldest dropped first.
  • Your summary prompt. You can write your own summarization prompt for when the default drops something a later turn needs.
  • Exact wording of old turns. Folded into the summary. The phrasing is gone, only the gist remains.
  • Full tool outputs and intermediate reasoning. Dropped first when space gets tight. Gone, not summarized.
  • Old thinking blocks. Stripped from history on many models, which quietly reclaims token capacity.
  • Path-scoped rules. Lost until a matching file is read again.
  • A rule you stated 20 messages ago. Summarized away, unless it lives in a file.
  • The details. "We refactored the auth module" survives. Which lines, which error, in which order: fuzzy.

Survival rules for Claude Code sessions, documented from Anthropic's own docs. The pattern generalizes: disk beats conversation, explicit beats implied, recent beats old.

4. Key voices

Five people and teams who built the machinery or documented it honestly. Each view is one or two sentences with the primary source linked. The real action is at the bottom, where two camps collide.

The real disagreement contested

Where should knowledge live: in the weights, or in files the model re-reads? Both camps ship products. Neither has won.

The parametric camp Meta FAIR
put it in the weights

Knowledge belongs in trainable memory layers: dedicated, cheap key-value storage inside the model itself. Files and prompts are a workaround. The architecture should remember, and their paper closes by advocating memory layers in all next-generation architectures.

The explicit camp OpenAI, Anthropic
put it in artifacts

Knowledge belongs in things the model re-reads: saved memories, memory files, CLAUDE.md on disk. Explicit, editable, inspectable, and it survives every compaction because it is re-injected, never summarized. Weights are where knowledge goes to become unverifiable.

The honest 2026 answer is that the best systems use both: memory layers for facts the model always needs, files and saved memories for everything personal, load-bearing, or likely to change.

5. What comes next

Every prediction below is attributed: who said it, where, when. The badge is my read of how solid it is: consensus means multiple independent sources agree, contested means smart people disagree, speculative means one party's leap. Predictions go stale; this section is frozen as of October 2026.

Berges et al. expect memory layers in all next-generation architecturesspeculative
Trainable key-value memory becomes a standard component, not an experiment: dedicated cheap storage for facts inside the weights, complementing dense layers rather than replacing them.
Said in "Memory Layers at Scale," Dec 2024 (revised Aug 2026).
Server-side compaction graduates from beta to the default agent primitivespeculative
Every long-running agent gets automatic summarization with recent turns preserved word for word. Raw conversation history stops being the default unit of context; the summary block becomes it.
Anthropic's docs already call compaction "the primary strategy" for long-running conversations; both flavors in beta as of October 2026.
Windows keep growing, and curation beats sizeconsensus
1M-token windows are already the default on current Claude models and keep getting cheaper (Haiku 5.5: $0.10 per million input tokens). But Anthropic's own docs warn of context rot: accuracy and recall degrade as token count grows, so the scarce skill becomes choosing what goes in, not how much fits.
Anthropic platform docs, Oct 2026; Haiku 5.5 pricing, Oct 7, 2026.
Two-layer cross-session memory becomes standardspeculative
Every assistant ships explicit saved items plus synthesized recall across past chats, the way ChatGPT has since the April 2025 expansion. The window stays the working memory; the profile becomes the long memory.
OpenAI's direction since Apr 2025; OpenAI help center, 2026.
The open fight: do big windows kill compaction?contested
One camp says a large enough window makes summarization unnecessary. The other says context rot makes compaction more important as windows grow, because quality degrades with size. Anthropic ships both a 1M default and a compaction beta, which is the tell: they are betting on both.
Anthropic platform docs, Oct 2026.
The per-token KV tax keeps shrinkingconsensus
Fewer KV heads (grouped-query and multi-head latent attention), lower precision, prefix reuse, and sliding windows keep cutting the memory cost of long context. The tax never hits zero, but the serving stack keeps refinancing it.
vLLM KV-cache explainer, 2026; PagedAttention serving notes.
