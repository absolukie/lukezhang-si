Two CI speedups, both free

engineering · tools · Oct 8, 2026

Two tips from @JinjingLiang, who builds the Orca project: replace ESLint with Oxlint, and run your GitHub Actions steps in parallel. One makes linting 32x faster, the other roughly doubles CI speed. Both cost nothing.

1. Fire your linter

ESLint is JavaScript checking JavaScript, one file at a time, slowly. Oxlint does the same job in Rust, across many threads. On the Orca repo (27,448 files, 4.61 million lines, 48 shared core rules, median of 10 runs each):

Lint time, Orca repo

Lower is better. Bars are to scale.

oxlint0.477s · 16 threads
ESLint15.60s · concurrency 8

That is 32.7x faster. The green bar is 3% the width of the red one. Fifteen seconds of linting is a coffee break your CI takes without asking.

Read the small print. Her benchmark ran with no lint cache, Oxlint is not type-aware the way ESLint with type rules is, and rule implementations differ between the tools. Your number will not be exactly 32.7x. The gap is big enough that the conclusion survives anyway.

If linting is one of your slowest CI steps, this is the cheapest win available: same rules you already use, a fraction of the time.

2. Let your steps run at the same time

GitHub Actions steps used to run strictly one after another inside a job. In June 2026, GitHub added parallel steps: wrap independent steps in a parallel: block and they run together.

steps:
  - uses: actions/checkout@v4

  - parallel:
      - name: Lint
        run: npx oxlint
      - name: Typecheck
        run: npx tsc --noEmit

  - name: Test
    run: npm test

Lint and typecheck run at the same time; tests still wait for both. Her testing showed roughly 2x CI speed from this alone.

Worth knowing: AI coding assistants usually miss this feature because it shipped after most of their training data. Check your own workflows by hand.
