FastAPI, explained

October 1, 2026 · python · apis

Verdict: FastAPI is the fastest way to turn a Python function into a production-grade API. You write a normal function with type hints, and you get request validation, JSON serialization, and interactive documentation for free. The "fast" refers to your development speed — but it's genuinely quick at runtime too.

The 30-second demo

This is a complete, working API:

from fastapi import FastAPI

app = FastAPI()

@app.get("/items/{item_id}")
def read_item(item_id: int, q: str | None = None):
    return {"item_id": item_id, "q": q}

Run it, and you get:

  • Validation. item_id: int means FastAPI rejects /items/abc with a 422 error explaining exactly what went wrong. You wrote zero validation code.
  • Docs. Visit /docs and there's a full interactive Swagger UI — try every endpoint from the browser, auto-generated from your type hints.
  • Serialization. Return a dict, a Pydantic model, a list — it becomes JSON with the right content type, automatically.

That loop — type hints in, validated API out — is the whole pitch. The framework reads the annotations you were probably writing anyway and does the boring plumbing for you.

What it actually is

FastAPI (by Sebastián Ramírez, first released 2018) is a Python web framework for building APIs — not websites with pages, but the JSON-speaking backends behind apps, SPAs, and services. It stands on two shoulders:

  • Starlette — handles the HTTP plumbing (routing, requests, websockets) on ASGI, Python's async server interface.
  • Pydantic — handles data validation using type hints. Its v2 rewrite (2023) moved the hot path to Rust, making validation dramatically faster.

Because it's ASGI-native, your endpoints can be async def, so one process can juggle thousands of concurrent connections — waiting on a database or another API doesn't block everyone else. That's a big part of why it benchmarks near Node and Go on TechEmpower-style tests despite being Python.

What it's useful for

  • Serving ML models. This is arguably its killer app. Train a model in Python, wrap inference in a FastAPI endpoint, deploy. Half the model-serving endpoints on the internet look like this.
  • Microservices and internal APIs. Small services that do one thing, speak JSON, and need to exist by Friday.
  • Backends for apps and SPAs. Your React/Flutter/iOS app needs /api/... — FastAPI is the shortest path from "idea" to "the app talks to a server."
  • Webhooks and glue code. Receive a POST from Stripe/GitHub/Slack, validate the payload, do a thing. Fifteen lines.
  • Prototypes that survive. Because validation and docs come free, the prototype you hack together in an afternoon is uncomfortably close to production-ready.

When not to reach for it

  • Server-rendered websites. If you want HTML pages with logins and templates, Django or Rails give you the whole kitchen. FastAPI can serve HTML, but that's not its home turf.
  • CPU-bound work. It's still Python — heavy computation blocks the event loop. Offload to background workers and keep the API thin.
  • When you don't know Python. Obvious, but: the magic is Python type hints all the way down.
The one-liner: FastAPI turns Python type hints into a validated, documented, production-ready API with almost no boilerplate — which is why it went from side project to the default choice for Python APIs in a few years.
