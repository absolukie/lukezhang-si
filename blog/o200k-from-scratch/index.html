o200k from scratch: 50 tokenizations

October 4, 2026 · ai · tokenizers

Verdict: I rebuilt GPT-4o's tokenizer from zero — no tiktoken, no libraries — and verified it byte-identical against the real thing on thousands of inputs. A tokenizer turns text into the integers a model actually reads, and its choices are weirder than you'd expect: the year 2026 splits as "202"+"6", the whole alphabet is a single token, and one family emoji costs 11 tokens. Below: how the machine works, 50 real tokenizations, and the regex bug hiding in plain sight.

The idea in one paragraph

A language model never sees letters — only integers. The tokenizer is the machine that converts between the two. GPT-4o's tokenizer, o200k_base, knows 200,019 integers: 256 for the individual bytes (so any text is encodable), 199,998 learned by merging frequent byte pairs in training data, and 2 special markers. To tokenize, it splits text with a regex, converts each piece to raw UTF-8 bytes, then repeatedly merges the adjacent pair with the lowest learned rank. That last step — byte-pair encoding — is the whole game, and it's 30 years old.

Byte-pair encoding, watched

Take the word "token". It starts as 5 raw bytes. At each step the pair with the lowest merge rank fuses — the ranks were learned from real text, so common letter pairs merge first:

flowchart TD
    S["t o k e n
5 bytes"] --> M1["merge e + n → en
rank 262"]
    M1 --> M2["merge o + k → ok
rank 525"]
    M2 --> M3["merge ok + en → oken
rank 2488"]
    M3 --> M4["merge t + oken → token
rank 10346"]
    M4 --> T["1 token: #15263"]
    style T fill:#e8a15c,stroke:#333,color:#000

Four merges and five bytes become one token (#15263). The algorithm never considers meaning — only which pairs were frequent in training. That's why the splits land on morpheme-like seams most of the time, and in strange places the rest of the time.

50 tokenizations

Every example below is real output from the from-scratch implementation (verified identical to tiktoken). Hover a chip for its token id. Amber chips are byte fragments — pieces of a UTF-8 sequence that only make sense together.

The basics
EXAMPLE 1 · 3 tokens
Hello world!
Hello ␣world !

'!' is token #0 — the single most common merge in the entire vocabulary. Exclamation marks earned the very first id.

EXAMPLE 2 · 2 tokens

A capital W with its leading space is its own token (#5922). Case changes everything.

EXAMPLE 3 · 3 tokens

Three tokens, and two are fragments ('HEL' 'LO'). The training data didn't shout much, so all-caps has no smooth encoding — shouting costs extra.

EXAMPLE 4 · 8 tokens

"It's" (#15834) and "isn't" (#12471) are each one token. The regex has a dedicated branch just for English contractions.

EXAMPLE 5 · 5 tokens
don't can't won't shouldn't couldn't

Five contractions, five tokens. Each one was frequent enough to own an id outright.

EXAMPLE 6 · 10 tokens

The ␣quick ␣brown ␣fox ␣jumps ␣over ␣the ␣lazy ␣dog .

Ten tokens, 4.4 characters per token — the going rate for ordinary English prose.

Spaces are tokens too
EXAMPLE 7 · 5 tokens
a b c
a ␣ ␣b ␣␣ ␣c

Note what's missing: there is no 'double-space then b'. A lone space, then the space glues to the following letter. (More on why in the detective story.)

EXAMPLE 8 · 5 tokens
leading and trailing
␣␣ ␣leading ␣and ␣trailing ␣␣␣

Spaces attach to the next word; a trailing run at the very end of text stays whole.

EXAMPLE 9 · 8 tokens
line one line two line three
line ␣one ⏎ line ␣two ⏎⏎ line ␣three

Newline is #198, double-newline is #279 — single tokens. Line breaks are cheap.

EXAMPLE 10 · 6 tokens

Tab+col fused into one token (#93902). The training data had enough tab-separated tables to weld them together.

EXAMPLE 11 · 10 tokens

Ten tokens along morpheme-ish seams: super|cal|if|rag|il|istic|exp|ial|id|ocious. Long words shred where the merges run out.

Twenty tokens. The year splits as '202'+'6', and $1,000,000 becomes 1|,|000|,|000 — commas split numbers too. Numbers are expensive.

The possessive-quantifier detective story

OpenAI publishes the pre-tokenizer regex with possessive quantifiers (?+, *+, ++) — matchers that never give characters back once matched. But tiktoken's core is written in Rust, and Rust's regex crate has no possessive quantifiers: it silently parses a++ as nested (a+)+, i.e. plain greedy. That changes real output:

flowchart TD
    R["published regex
possessive quantifiers
a++  ?+  *+"]
    R --> PY["Python regex module
true possessive semantics"]
    R --> RS["tiktoken Rust core
regex crate has no possessive
a++ parsed as (a+)+ = greedy"]
    PY --> PO["a  b becomes: a / double-space / b"]
    RS --> GR["a  b becomes: a / space / space-b"]
    GR --> TK["tiktoken output"]
    style TK fill:#e8a15c,stroke:#333,color:#000
    style PO fill:#f6f6f6,stroke:#999,color:#333

So the published pattern and the running code disagree — and the code wins. My implementation matches tiktoken's actual behavior. Amusing footnote: tiktoken's own pure-Python encode_ordinary path uses the regex module, which does implement possessive — so tiktoken disagrees with itself depending on which door you enter through.

The 7 regex branches

Before any merging happens, the regex decides the maximum span a token may cover. Merges never cross a regex boundary, which is why a script change (Latin → Chinese) or a digit limit always splits:

    P["next position in text"] --> B1["word +
contraction?
don't"]
    P --> B2["ALL-CAPS word
NASA"]
    P --> B3["number, max 3 digits
123"]
    P --> B4["punctuation run
!!!"]
    P --> B5["newlines
newline newline"]
    P --> B6["trailing whitespace
end of text"]
    P --> B7["other whitespace"]
    B1 & B2 & B3 & B4 & B5 & B6 & B7 --> N["one piece: merges never cross it"]

The 256 byte tokens are the escape hatch: because every byte is in the vocabulary, every Unicode string has exactly one encoding — even text the tokenizer never saw in training. The 19 unassigned ids are just gaps OpenAI left in the numbering.
